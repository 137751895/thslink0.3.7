# ThsLink-Cli（纯接口版）

本版只提供 HTTP 接口，无窗口、按钮、热键和图形渲染依赖。与桌面版共用交易、数据查询、请求编号关联及回执实现。当前版本为 v0.3.8，修复官方独立下单 2023.03.30.0 在部分电脑上误报不兼容的问题，保留普通委托、成交的原生缓存展示；保留 DLL 自动重连与安全重载、未确认结果持久保存及旧请求实例隔离，恢复不会重发交易。桌面版与纯接口版同步发布，须整体使用同版本包。

本包与桌面版共用交易和回执处理。等待某笔结果时可以继续提交后续命令，每笔结果按自己的请求编号更新。返回中的跟踪编号只用于对应请求，不是券商合同号；字段与等待规则见同包内 `使用说明.md`。升级时请整体替换下载包，服务端、虚拟机与本机使用方式相同，不依赖弹窗或 GUI 轮询。

主程序、桥接 DLL 和加载器必须整体使用同一版本，不要只换 EXE 或混用旧 DLL。

信用业务使用统一的 `-module pyd` 参数规则，不按交易端日期限制。信用全撤 JSON：`{"side":"cancel","code":"all","credit":true,"module":"pyd","notip":true}`。本机 / 远程生成器、Python / cURL 及单笔 / 批量使用一致规则；普通交易、查询不加信用模块字段。旧客户端省略模块仍兼容；错误模块值和业务冲突会拒绝。

本版包含 2026.10.20 信用表名、账户选择和短合同号回执修复。信用业务、查询与撤单仍须根据实际券商和交易端分别核对；原生接口、对象布局、账户身份和查询完整性校验继续保留。

## 使用

1. 整体解压，保持 `ThsLink-Cli.exe`、`thslink_bridge.dll`、`thslink-load.exe` 在同一目录。
2. 编辑同目录 `http-config.json`，先启动并登录同花顺交易端，再双击 `启动 ThsLink-Cli(点这个).bat`。
3. 成功启动后显示监听地址；用 Python 或其他 HTTP 客户端调用。关闭服务使用控制台 Ctrl+C。

双击 EXE 也会启动服务并显示控制台。需要先检查配置时执行 `ThsLink-Cli.exe --check-config`；指定另一份配置用 `ThsLink-Cli.exe --config "C:\路径\http-config.json"`。配置修改后重启生效，不读取桌面版 AppData 设置。首次启动或执行 `--check-config` 时，若配置不存在或密码为空且验证开启，会生成并保存随机密码；保存失败不启动。已有密码不替换。

| 配置 | 默认 | 含义 |
|---|---|---|
| host | 127.0.0.1 | 监听 IP。局域网调用设为 0.0.0.0，并用服务器实际 IP 访问 |
| port | 8421 | 监听端口 |
| auth_enabled | true | 默认开启密码验证；只有明确设为 false 才关闭，关闭时保留原密码 |
| api_key | 首次生成 64 位十六进制随机密码 | 开启验证时所有接口均需 X-API-Key 请求头；重启沿用，日志不输出密钥 |
| terminal_path | null | 自动寻找交易端；有多个交易端时填写指定 xiadan.exe 的完整路径 |
| connect_bridge | true | 启动时连接交易端。false 只跳过启动连接，用于离线接口检查，不是禁止交易开关 |

当 `host` 是 `127.0.0.1` 或 `::1` 时，服务仅本机可访问。监听 `0.0.0.0`、局域网 IP 等非本机地址时，请设置强 API 密钥并配置防火墙；只有手动关闭密码验证后才允许免密调用，此时网络可达的客户端均可调用查询和交易接口。HTTP 本身不加密传输密码。

启动时端口占用会在连接交易端前报错。交易端连接失败时 HTTP 仍可启动，`/health` 反映实际通道状态；开启 `connect_bridge` 时，交易端登录后会继续自动连接，也可输入 `3` 主动连接。桌面版与 HTTP 版共用单实例锁和 DLL 通道，同一会话内只能运行其中一个；重复启动会显示正在运行的产品、PID、版本和路径。旧版本无法提供身份时显示占用者未确认，不猜测 GUI/CLI。

## 控制台菜单和连接状态

输入编号或命令后按回车：`1` / `s` 查看状态，`2` / `h` 查看接口和 JSON 用法，`3` / `r` 连接交易端，`4` / `config` 设置接口，`5` / `review` 人工核对不确定结果，`0` / `q` 安全退出。菜单不会执行输入的买卖撤单命令。帮助中的交易 JSON 仅作示例。

状态显示监听地址、密码验证是否开启、配置文件位置和 DLL 连接信息，不显示密钥内容。开启 `connect_bridge` 后每 5 秒触发自动恢复，和桌面版共用恢复逻辑；输入 `1` 可主动刷新。先尝试连接、必要时加载 DLL，累计 3 次连接失败后尝试安全卸载并重新加载；完整重载至少间隔 30 秒，失败持续重试，没有次数上限。恢复在后台执行，单次超过 1 秒会显示“自动连接/恢复正在后台进行”，控制台继续响应。未确认交易结果先归档，不单独阻止恢复；原生任务或回调仍在执行时暂不卸载。恢复记录保存到 `%LOCALAPPDATA%/ThsLink/request-history.jsonl`，未知结果不重发、不伪造成功。此状态表示 DLL 通道可通信，不表示券商交易服务器一定可用。

`connect_bridge=false` 时不主动探测 DLL；输入 `3` 成功连接后启用监测。连接操作只加载或确认 DLL 并准备执行器，不强制卸载旧 DLL，也不重发历史委托。未完成请求期间拒绝连接操作。

菜单 `4` 按顺序设置监听地址、端口和接口密钥。回车保留原值；密码步骤输入 `show` 查看、`new` 生成新密码、`-` 关闭验证、`+` 重新开启，或输入自定义密码并开启验证；任一步输入 `back` 取消且不写入配置。输入密钥会显示在当前控制台，请在自己的电脑上操作；密钥不会写入运行日志。关闭验证会显示免密访问提示；非本机监听也允许明确关闭，建议保持验证开启。成功保存后输入 `0` 退出并重新启动；当前服务继续使用原配置，不会在设置过程中中断在途请求。交易端路径和启动连接开关仍通过配置文件设置。

## 接口与日志

接口路径和 JSON 契约与桌面版一致，详细说明见随包 `使用说明.md`。

信用交易请只登录一个账户，使用当前账户：省略 `account` 或填写 `"current"`。例如融资买入的请求正文为 `{"side":"buy","code":"000001","price":"zxjg","amount":100,"xytype":3,"module":"pyd","notip":true}`。`xytype` 编号为 1 担保品买入、2 担保品卖出、3 融资买入、4 融券卖出、5 买券还券、6 卖券还款；买入类用 `buy`，卖出类用 `sell`。普通交易省略 `xytype`。四类查询手动传 `"mode":"ordinary"`（普通）或 `"mode":"credit"`（信用），省略固定为普通；不自动识别或切换。查询不加信用交易参数，`/who` 仍直接读取账户信息。信用全撤请求为 `{"side":"cancel","code":"all","credit":true,"module":"pyd","notip":true}`，撤当前票将 `all` 换成股票代码。用户请求中 `credit` 与 `xytype` 不能混用；选择信用业务时由命令生成阶段直接产生完整参数，预览、复制与提交一致。旧客户端省略 module 的请求保留兼容处理。

所有交易必须显式填写布尔 `notip: true`，批量逐笔填写。`http_demo.py` 的交易函数自动补齐该参数；直接运行示例只检查健康和账户。

按单个合同号撤单使用 `POST /order`，例如 `{"side":"cancel","contract":"00123456","notip":true}`。`contract` 用字符串保留前导零，与 `code` 二选一，不填写价格或数量；批量逐笔使用同样字段。信用合同撤单再填写 `"xytype":1,"module":"pyd"`，不填写 `credit:true`。Python 示例提供 `cancel_contract`。

数据查询任务从创建起共用 5 秒预算，HTTP 的 `wait_ms` 默认 2000，范围 0～5000；HTTP 先返回 pending 时继续轮询原查询编号。超时账户在下一次结果轮询或查询准入检查时结束本次等待、清空未完成表并释放查询通道；信用撤单准备使用相同预算，清单超时则本次不发送撤单。后续可重新查询，迟到响应不复活旧结果、不触发信用撤单。这会结束 ThsLink 自己的等待，不会取消同花顺内部请求，原生线程或回调自身卡住仍需单独处理。`unchanged / #noup#` 则表示本次原生没有发布新快照，和超时不同，不能当成没有委托或成交。返回的 `native_return_code`、`packet_status` 和 `sequence` 可辅助定位问题。

运行状态和错误同时输出至控制台、EXE 同目录 `http-service.log`。超过约 2 MiB 时保留一份 `http-service.previous.log`，不记录请求业务内容。可选深层诊断仍使用既有 diagnostics 机制。

菜单 0/q 或 Ctrl+C 请求安全退出：先暂停新任务，再检查客户端与 DLL 的交易、回执、查询及账户操作；空闲时安全停止 DLL，并通过交易进程的模块列表确认 DLL 已卸载后退出。交易端本身继续运行。有未完成请求、未知结果、旧版 DLL 身份不可验证或卸载未确认时，安全退出被拒绝，程序显示原因及退出选项：输入 force（也可输入 f 或 1）立即强制退出 ThsLink 和 HTTP 服务；输入 back 继续运行。强制退出不关闭交易端、不强制卸载 DLL；DLL 可能仍驻留，未确认退出记录保留。退出不撤销已提交委托，也不自动重发。

结果不确定时，先在券商当日委托/成交中核对，再输入菜单 5，从列表序号选择待核对的记录，输入 `y` 确认。无需手填 DLL 请求编号或 local 编号。仅解除生命周期保护，原始回执保留，不伪造交易成功。原生交易提交调用或关联任务仍未完成时，不能人工确认解除卸载保护。只读查询超时会结束本次等待；重连或退出时仍会关闭观察入口并等待活动回调退出，真正卡在原生调用中的线程仍会阻止卸载。

控制台右上角关闭、任务管理器强制结束、系统关闭或程序崩溃可能由 Windows 直接终止进程，不能保证执行安全卸载；推荐使用菜单 0/q 或 Ctrl+C。下次启动显示上次未确认退出的记录，实际是否残留 DLL 以身份/模块检查为准。请求与回执证据持久保存到 `%LOCALAPPDATA%/ThsLink/request-history.jsonl`，重启后恢复待核对记录；文件包含交易命令、账户选择参数及回执，请按交易记录保管。调用方仍应保存完整业务日志、请求编号和返回值；结果不确定时禁止自动重发。

本版没有自动更新器、Windows 服务安装或后台守护。运行时请保持 Windows 用户已登录，并让同花顺交易端正常打开。

## 编译

```powershell
cargo build --manifest-path ordertool/thslink/Cargo.toml --release --no-default-features --features http --bin thslink-http --locked
```

桌面版产品名称显示为 `ThsLink`；纯接口版产品名称为 `ThsLink-Cli（纯接口版）`。Cargo 内部构建 target 仍叫 `thslink-http`，安装包中的程序文件名为 `ThsLink-Cli.exe`。

桌面版使用默认 desktop 功能，构建时可指定 `--bin thslink`。DLL 和加载器继续复用同版本构建。打包运行 `ordertool/整理纯HTTP版.ps1`；默认生成本地测试包；正式发布由 `发布版本.ps1` 调用 `-Release`，两个版本共用已提交源码和同版本桥接组件。

## 兼容、权限与诊断

固定兼容路径覆盖普通版 2026.07.02.0、2026.09.15.0、远航版 2026.05.06.0 和 2026.10.20.0。未知构建须通过自动发现和严格验证；只有唯一候选且所有接口契约均匹配时才启用。其他结构或接口逻辑发生变化时可能需要适配，不能保证后续版本无需修改。信用交易请只登录一个账户，并使用当前账户；六类业务、所有查询、切换及多账户信用交易未全面验收。

本版对已知与未知构建检查完整指令、调用关系、账户 / 查询结构和任务回执，候选有歧义时拒绝。仅对已审阅的地址、部分指令填充和分支位置变化及可证明的查询连接栈槽变化自动调整；异常处理、外部引用或业务结构无法确认时不会猜测兼容。

桌面与纯 HTTP 共用相同桥接适配器。INFO 以及 HTTP `/health` 的 `bridge.automatic_adaptation` 提供布局族、匹配模式、调整角色、连接栈偏移和扫描耗时。首次 INFO/READY 初始化最多等待 60 秒，随后使用缓存；交易超时规则、后台短探测和不自动重发规则不变。适配只读取本地交易端映像，不联网下载规则，不通过发送订单 / 撤单探测兼容性。

启动和菜单 1 显示交易端文件版本、PID、路径和权限原因；文件版本读取不依赖 DLL 连接，能显示版本不代表已经兼容。连接前比较 ThsLink 与交易端权限；交易端以管理员运行而本程序权限普通时，应退出 ThsLink 后以管理员身份运行。程序不自动提升权限。

`ThsLink-Cli.exe --check-terminal` 只输出版本和权限信息，不取得单实例锁或加载 DLL。HTTP /health 的 terminals 返回同样元数据。详细诊断默认关闭，在程序目录创建 `diagnostics/enabled` 空文件可开启；若使用本地用户 ThsLink 诊断目录中的全局标记，还须在当前程序目录创建 `diagnostics.use-global` 空文件，避免继承旧版排查设置。技术日志按大小轮换，记录调用与通信阶段，不作为券商成交凭据。正常缓存读取与诊断开关独立，适用范围及缓存状态见使用说明。

HTTP 的 batch_id 自 v0.2.8 起为 GUID 字符串，请原样保存。批次 complete 仅表示成员完整，不表示全部成功；回执查询错误不等于原订单拒绝。

当前异步实现中，正常异步任务没有即时回执不会阻挡后续提交；30 秒超时后仍按原编号跟踪。提交前检查、行情读取、锁或分发本身若卡住，后续新单仍可能被串行保护挡住。未完成和不确定请求达到容量上限时会拒绝新请求。超时不取消委托，不自动重发或重启交易端。当前版本还保留此前修复：旧等待状态覆盖明确回执、任务释放时误用部分返回、批量提示换行破坏记录边界，以及同花顺没有提供新查询结果时被误报为 HTTP 502 的问题。
