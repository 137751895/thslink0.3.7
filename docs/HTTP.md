# ThsLink 使用说明 · HTTP 调用（v0.3.8）

## 当前版本与兼容范围

本说明对应 **v0.3.8**。本版修复官方独立下单 `2023.03.30.0` 在部分电脑上误报不兼容的问题，保留该版普通委托、成交的原生缓存展示，以及桌面版与纯接口版统一的 DLL 自动重连与安全重载。未确认交易结果持久保存，旧请求按 DLL 实例隔离，恢复不会重发交易。固定兼容路径覆盖 32 位 `xiadan.exe` 普通版 `2026.07.02.0`、`2026.09.15.0` 及远航版 `2026.05.06.0`，并支持通过严格校验的 `2026.10.20.0` 与官方独立下单版。未知构建须通过完整自动发现与严格验证；版本日期相近不能保证兼容。

官方独立下单 `2023.03.30.0` 已通过账户列表、当前账户、普通持仓/委托/成交/资金查询及安全重载验证。成交查询主动请求完整数据；真实分页或增量响应仍标为 `partial`。普通委托、成交在收到无更新响应时，可在通过缓存校验后展示同账户原生缓存，仍保留无更新与时效、完整性待确认状态。实际买卖、撤单、账户切换和信用查询尚未在该版现场验收。

既有普通账户读取、四类查询及 DLL 安全卸载/重连均保留。用户已在当前 10.20 环境反馈信用账户信息可读取、当日委托可查询，且信用撤单验收通过；这不代表所有信用业务、查询、多账户或其他券商都已验收。桌面版与纯接口版请整体使用同一构建的包，先核对未确认委托，再安全退出旧客户端并确认 DLL 卸载；只换 EXE 不会更新已加载的旧 DLL。交易端为管理员权限时，新客户端也需以管理员权限启动。

桌面版 ThsLink 与 ThsLink-Cli-纯接口版共用以下 HTTP 接口。纯接口版启动与菜单配置见同包内 `纯HTTP版说明.md`；桌面版从界面设置接口。

ThsLink 仅供个人非商业学习与研究使用，不允许用于商业行为；完整条款见 [项目许可](../LICENSE.md)。

ThsLink 支持本机、局域网及服务器远程 HTTP 调用、单笔与批量交易、多账户买卖撤单。

ThsLink 把桌面操作、HTTP 请求和 CLI 命令送到同花顺 `xiadan.exe` 内的桥接 DLL，通过进程内原生命令执行器提交并接收内部返回结果。持仓、当日委托、当日成交、资金查询使用独立的内部查询请求和对应响应结果表。

当前版本的提交参数与同花顺自身 Python `cmd` 使用的 `sync=0, source=0` 一致，已移除旧同步等待模式。提交调用仍短暂串行；已绑定的第一笔任务等待回执时，不再因此阻挡下一笔或中断批次。同花顺确认任务全部关联明细完成时保存回执，按原请求编号读取。主程序与 DLL 须一起更新。若派发函数本身异常不返回，仍保护共享执行器；异步不意味着任意内部故障均不会影响后续提交。

## 绿色便携版启动

解压完整便携包，保留 `thslink.exe`、`thslink_bridge.dll`、`thslink-load.exe` 在同一目录，双击 EXE 使用，无需安装或 CMD。桌面版下载 Release 附件 `thslink-windows.zip`，纯接口版下载 `ThsLink-Cli-windows.zip`，不要使用 GitHub 的 Source code 压缩包。

Windows 10/11 x64；桥接组件用于 32 位 `xiadan.exe`。先登录同花顺交易端，再启动 ThsLink。更新时退出两者并整体替换文件；不要混用新旧 DLL。内部接口与交易端版本有关，不匹配时拒绝连接。

主窗口支持拖动四边和四角调整宽高，默认大小保持原样。停止拖动后保存尺寸，下次启动恢复；最小化时不覆盖已保存的尺寸。窗口尺寸保存在原有的 `ui-settings.json`，打开编辑页后再调整主窗口并保存编辑，也会保留最新尺寸。原生标题栏的兼容模式同样支持调整。

## 启动与接口设置

先启动同花顺并登录账户，再启动 ThsLink。首次使用时打开主界面的“接口”开关；开关状态会保存，以后启动自动恢复，手动关闭后下次保持关闭。

- 默认地址：`http://127.0.0.1:8421`。
- 主窗口“HTTP 接口”右侧的“API 密钥”开关控制密码验证，与设置页同一选项联动；点击即保存。关闭验证保留原密码，重新开启可复用；HTTP 未启动时切换此开关不会自动启动接口。
- 设置中可以修改监听 IP、端口和 API 密钥；密码可显示、复制或重新生成。
- 局域网调用：监听 IP 设为 `0.0.0.0`，其他电脑使用运行 ThsLink 电脑的局域网 IP 和端口；Windows 防火墙须允许该端口。`0.0.0.0` 是监听配置，不是客户端请求地址。
- 默认开启密码验证：首次启用 HTTP 自动生成并保存独立随机密码，每次请求携带 `X-API-Key: 你的密钥`。重启沿用原密码；已有自定义密码不替换。可手动关闭验证，关闭后保留原密码但不再校验。
- 开关、地址、端口及密钥保存在 `%APPDATA%/thslink/ui-settings.json`；绿色便携版更新不覆盖配置。同一 Windows 用户移动软件目录后也继续使用已有配置。
- 关闭“手动交易”后，停止自动读票、股票跟随与交易热键，界面显示“读票暂停”；HTTP 请求、DLL 连接维护和后台回执继续工作。重新开启手动交易后恢复读票。

命令行 `thslink.exe ui --http` 启动界面和 HTTP，使用桌面版 AppData 设置；`thslink.exe serve` 仅运行 HTTP，读取 EXE 同目录的 `http-config.json`，不存在时创建默认 `127.0.0.1:8421`、随机密码和自动连接交易端配置。旧配置空密钥且未明确关闭验证时也会生成并保存密码；保存失败不启动接口。`serve` 使用与纯接口版相同的控制台菜单，配置保存后重启生效，不读取桌面版 AppData 设置。

## 连续调用：复用 HTTP 连接

服务端默认支持 HTTP Keep-Alive。POST、GET 都可以复用连接，接口地址和 JSON 参数不用改。本机、局域网和远程调用都适用。

| 什么时候 | Python 应该怎么做 |
|---|---|
| 你的 Python 程序启动 | 创建一次 `session = requests.Session()` |
| 每次下单或查询 | 使用同一个 `session.post(...)` 或 `session.get(...)` |
| 轮询回执或查询结果 | 继续使用这个 Session，不重新创建 |
| 你的 Python 程序退出 | 调用 `session.close()`；下面示例用 `atexit.register(session.close)` 在正常退出时清理 |

不要在每次调用的函数或循环里新建 Session，也不要每发一笔就关闭。下面各示例可单独运行；合并到同一个策略程序时，只保留一份 Session 初始化，后续请求共用它。示例按顺序调用；多线程程序建议每个工作线程长期保留自己的 Session。

仅添加 `Connection: keep-alive` 请求头不够：调用端销毁客户端后，连接就无法继续复用。使用 Session 时通常不需要手动添加这个请求头。示例默认完整读取响应；如果改成 `stream=True`，要读完响应体或关闭响应，连接才能归还连接池。

复用不代表连接永不断开：服务端重启、网络变化或中间设备超时仍可能断开连接。后续请求可建立新连接；交易 POST 超时或断线后，先核对原请求回执或当日委托，不自动重发。示例没有启用交易失败自动重试。

## 局域网与多账户

局域网调用时，同花顺和 ThsLink 留在服务端电脑，另一台电脑通过 HTTP 提交请求并查询回执。客户端不需要安装 ThsLink。监听地址设为 `0.0.0.0`，开启接口，修改监听设置后重启接口；请求使用服务端电脑的实际局域网 IP 和端口。先用 `GET /health` 检查连通性。

普通交易的买入、卖出、撤单支持以下多账户用法；信用交易请只登录一个账户，并使用当前账户：

| 账户范围 | 请求字段 | 含义 |
|---|---|---|
| 当前账户 | 不填 account | 使用同花顺当前账户 |
| 指定账户 | `"account":"ACCOUNT_ID"` | 换成实际已登录账号，无需先手动切换当前账户 |
| 全部账户 | `"account":"all"` | 对当前交易端全部已登录账户执行指令 |

批量中每笔分别设置账户范围。`account=all` 只涵盖已登录账户，不会自动登录其他账户。本机、局域网和服务器远程请求使用同一套接口和后台回执链路。

## 服务器部署与远程调用

同花顺和 ThsLink 在同一台 Windows 服务器运行。远程调用可通过 VPN 地址，或自行配置带身份认证的 HTTPS 入口；ThsLink 本身提供 HTTP，没有内置 HTTPS 证书或 VPN。请求参数与本机调用相同，客户端继续复用 HTTP 连接。

也就是说：服务器负责运行同花顺、登录账户和执行交易；你自己的电脑或另一台服务器运行 Python 等调用程序，通过网络发送请求。不要求两台电脑在同一个局域网，只要调用端能访问服务器的接口地址即可。服务器须具备可运行同花顺交易端的 Windows 桌面环境，交易端和 ThsLink 均需保持运行。

| 部署方式 | 调用端填写的接口地址 | 需要配置什么 |
|---|---|---|
| 同一台电脑 | `http://127.0.0.1:8421` | 使用默认本机监听地址 |
| 同一局域网 | `http://服务器局域网IP:8421` | 监听可访问的网卡地址或 `0.0.0.0`，允许防火墙端口 |
| 跨网络，通过 VPN | `http://服务器VPN地址:8421` | 两端加入 VPN，监听 VPN 网卡地址或 `0.0.0.0`，允许对应网络访问 |
| 跨网络，通过 HTTPS 入口 | `https://你的接口域名` | 配置域名、证书、身份认证和反向代理，转发到 ThsLink 的 HTTP 端口 |

将调用代码中的 `BASE` 换成对应地址，继续携带 `X-API-Key`，并复用同一个 `requests.Session()`。POST / GET、JSON 参数、查询和回执用法都相同。公网不建议直接暴露明文 HTTP 交易端口，优先使用 VPN 或 HTTPS 入口。

## 主动查询持仓、当日委托、当日成交和资金

查询链路：调用同花顺内部查询工厂 → 在交易端 UI 线程提交请求 → 跟踪请求复制及通信序号 → 等待对应响应处理完成 → 复制本次结果表 → 返回 JSON。无需打开查询页面，不通过读取界面控件代替主动查询。精确匹配的 2026.10.20.0，以及通过缓存专用契约核验的官方独立下单 2023.03.30.0，普通委托、成交查询收到 #noup# 时，会尝试读取同账户、同查询类型的原生缓存；仍保留 unchanged、complete=false，并标记 cached=true、source=native_request_cache、freshness=unknown、completeness=unknown。2023 使用本版带锁深拷贝接口，不复用旧版地址和对象布局；仅允许已验证的模块基址与系统接口跳板，其他布局跳过缓存回退。缓存读取独立于诊断开关，其他版本与信用查询保持原路径，缓存不用于信用可撤清单。

查询支持 POST /query（JSON 请求体）或 GET /query/{kind}（地址参数），二选一即可。两种方式都不会创建买卖撤单或交易流水。使用与交易接口相同的监听地址和 X-API-Key。

| 参数 | 是否必填 | 填写方式 |
|---|---|---|
| kind | POST JSON 必填 | holdings 持仓、orders 当日委托、deals 当日成交、funds 资金；GET 写在路径里 |
| account | 可选 | 默认 current：当前账户；实际已登录账户号：指定账户；all：全部已登录账户，无需切换当前账户 |
| mode | 可选，建议明确填写 | ordinary：普通查询；credit：信用查询。省略为 ordinary，不自动识别或切换；all 对所有目标使用同一模式 |
| wait_ms | 可选 | 默认 2000 毫秒，范围 0～5000；0 表示提交后立即返回查询编号 |

示例地址：`GET /query/holdings?account=current&mode=ordinary&wait_ms=2000`。

| 查询内容 | GET 路径（无 JSON 请求体） |
|---|---|
| 持仓 | `/query/holdings?account=current&mode=ordinary&wait_ms=2000` |
| 当日委托 | `/query/orders?account=current&mode=ordinary&wait_ms=2000` |
| 当日成交 | `/query/deals?account=current&mode=ordinary&wait_ms=2000` |
| 资金 | `/query/funds?account=current&mode=ordinary&wait_ms=2000` |
| 获取本次结果 | `/queries/QUERY_ID`，替换为返回的 query_id |

全部账户资金示例：`http://127.0.0.1:8421/query/funds?account=all&mode=ordinary&wait_ms=2000`。指定账户时把 current 换为实际已登录账号；局域网调用将地址中的 127.0.0.1 换为服务端电脑 IP。`/query/orders` 查询当日委托表，`/orders/:id` 获取某笔交易请求的回执，两者不同。

| 返回字段 | 含义 |
|---|---|
| query_id | 本次查询编号，与交易 request_id 分开；用 GET /queries/编号 继续读取 |
| mode | 本次选择的查询模式 ordinary / credit；账户实际类型仍见 accounts[].account_type |
| source | native_query：来自本次内部查询响应 |
| status | pending 等待中；complete 全部账户完整完成；partial 部分数据；unchanged 同花顺未发布新的结果快照；error 查询失败 |
| complete / success | 所有目标账户都完整完成时才为 true |
| accounts | 各账户结果，包含 account、name、account_type、status、error、sequence、elapsed_ms、tables |
| accounts[].native_return_code / packet_status | 本次原生响应的处理返回值和包状态；尚未收到时为 null。返回值 8 对应原生无更新分支，和结果表字段识别失败分别报告 |
| accounts[].response_tracked | 是否仍保留该请求的响应归属记录；仅用于诊断，不表示成功或占用整个查询通道 |
| tables | 该账户收到的原始市场结果表；不同市场分开返回 |
| columns | 每列元数据；用 name 与 rows 字段对应，不一定包含中文 caption，不能假定所有列都有中文名称 |
| rows / row_count | 数据行与条数；普通字段值为字符串，保留交易端文本格式；重复颜色字段的规则见下文 |
| page_next | 后续页游标；非空表示仅收到部分页面，不是完整结果 |

部分交易端资金表会重复返回 `FCOLOR`、`BCOLOR`（界面颜色字段）。`columns` 保留原始列名与顺序；同名颜色列的值在 `rows` 中按出现顺序保存为字符串数组，例如 `"FCOLOR": ["原第9列值", "原第25列值"]`，不覆盖或丢弃任何一个值。没有重复时仍为字符串。业务字段重名仍报告错误，避免误读金额或数量。

空表与失败不同：完整响应中 row_count=0 表示没有记录；`unchanged` 表示本次没有新的结果快照，不能据此判断有没有记录，也不能拿旧表代替本次结果；无对应表、响应错误、超时或结果超出容量均明确报告错误。不要仅看 HTTP 200；`partial` 和 `unchanged` 的 `complete` 都是 false，必须检查账户状态。

```python
import time
import atexit
import requests

# 程序启动时只创建一次；后续下单、查询和轮询共用这个 session。
# 不要放进每次调用的函数或循环里反复创建。
session = requests.Session()
atexit.register(session.close)  # 程序正常退出时关闭连接池

base = "http://127.0.0.1:8421"
headers = {"X-API-Key": "填入设置中的密码"}  # 仅手动关闭验证后可使用 {}
response = session.get(base + "/query/holdings",
    params={"account": "current", "mode": "ordinary", "wait_ms": 2000}, headers=headers, timeout=30)
response.raise_for_status()
result = response.json()
while result["status"] == "pending":
    time.sleep(0.1)
    response = session.get(base + f"/queries/{result['query_id']}", headers=headers, timeout=30)
    response.raise_for_status()
    result = response.json()
if not result.get("complete"):
    raise RuntimeError(result)
print(result["accounts"])
# 其他类型：/query/orders、/query/deals、/query/funds
# 全账户：params 中 account 改为 "all"；指定账户改为实际已登录账户号。
```

HTTP 202 表示仍在查询，请读取原 query_id，不要重新请求 /query/holdings。一次只处理一个查询任务，all 在同一任务内覆盖全部已登录账户（最多 32 个）。请求处理超时为 5 秒；结果最多保留最近 8 次、每次 120 秒，DLL 重启后失效。每账户结果最多 4 MB、整次最多 8 MB，最多 10000 行、128 列；超限不返回伪装完整的截断数据。

查询任务从创建起共用 5 秒预算；到期后仍未完成的账户返回 `status: timeout`，在下一次结果轮询或查询准入检查时结束等待并释放查询通道，可以重新发起只读查询；超时账户的未完成表会清空。信用撤单准备阶段使用同一预算，清单超时则结束准备，本次不发送撤单。迟到响应仅用于结束旧请求的跟踪，不会把超时改成成功，也不会触发信用撤单。排队过期、尚未开始提交的任务返回“本次未发送”。此超时结束 ThsLink 自己的等待，不会取消同花顺内部已发出的请求；原生线程或回调自身卡住仍需单独处理。重连或退出仍会关闭并等待正在执行的观察回调，避免卸载时回调仍访问 DLL。

部分账户持续返回 `unchanged / #noup#` 时，不要当成没有委托或成交。它表示原生响应没有发布新快照，不能仅凭这一项认定是券商故障或表名过滤错误。请保留本次 `query_id`、各账户的 `sequence`、`native_return_code`、`packet_status` 和状态；诊断日志另外记录请求类型、刷新标志和每个目标索引，不记录账户号和数据行。多账户查询使用指定身份发起请求，不自动切换当前账户；不同券商账号的实际回包仍需分别验证。

内部接口与同花顺版本绑定，入口签名不匹配时明确拒绝。含分页游标的响应返回 partial 和已收到页面，目前不自动追取后续页。资金常用字段：xd_2112 余额、xd_2116 可用金额、xd_2191 总资产、xd_2973 总市值；持仓常用字段：xd_2102 股票代码、xd_2103 名称、xd_2117 数量、xd_2121 可用数量。另有 xd_2113 冻结金额、xd_2114 可取金额、xd_2125 市值、xd_3710 实际金额、xd_2172 币种。各字段独立保留，不能仅因数值相同就合并。界面只展示名称已确认的资金字段；HTTP 和复制 JSON 保留完整原始字段，包括内部编号、空值和原始数值文本，不新增盈亏字段或自行计算。

## 单笔请求

以下 JSON 发送到 `POST /order`：

```json
{"side":"buy","code":"000009","price":"mrxjg","amount":100,"notip":true}
```

| 参数 | 填写要求 | 含义与示例 |
|---|---|---|
| side | 必填 | buy 买入、sell 卖出、cancel 撤单 |
| code | 买卖必填；撤单与 contract 二选一 | 六位股票代码字符串；全撤填 all；按合同号撤单时省略 |
| contract | 按合同号撤单时填写 | 单个纯数字合同号字符串，例如 "00123456"，保留前导零；与 code 互斥，不填价格和数量 |
| price | 买卖必填 | 价格关键字或指定价格字符串，例如 mrxjg 或 "7.00"；撤单不填 |
| amount | 买卖数量五选一 | 股数，正整数；1 手填 100 |
| m | 买卖数量五选一 | 金额，单位元 |
| cw | 买卖数量五选一 | 买入按可用资金比例；卖出按可卖数量比例 |
| zzc | 买卖数量五选一 | 本次交易金额占账户总资产的比例 |
| zcw | 买卖数量五选一 | 交易后这只股票还剩多少仓位（占账户总资产）；卖出填 0 表示清仓 |
| account | 可选 | 省略：当前账户；ACCOUNT_ID：指定已登录账户；all：全部已登录账户 |
| xytype | 信用交易填写 | 1～6 的业务编号，完整对应表见“信用交易”；普通交易省略。信用交易请只登录一个账户，使用当前账户 |
| credit | 信用全业务撤单填写 | true 用于 cancel all 或指定股票；省略 / false 为普通撤单；不能与 xytype 混用 |
| module | 信用请求统一生成 | 字符串 "pyd"；四个版本及通过兼容检查的新构建采用相同参数，不按版本指纹限制。本机/远程生成器均带入；普通交易和查询不填 |
| notip | 必填，必须为 true | 跳过同花顺确认提示；漏填或 false 返回 HTTP 400，本次未发送。批量每笔均须填写 |
| zdky | 可选，仅买入 | 资金不足时按最大可买数量提交 |

数量参数只选一种。cw、zzc、zcw 支持小数或分数；小数 0.1 是 10%，分数须写字符串 "1/10"。zcw 是交易后的目标仓位，不是这次交易的比例。

提供 `account` 时必须使用字符串，数字账号应保留前导零。数组、对象、JSON 数字、布尔值、null 或空字符串会返回 HTTP 400；批量中任一笔账户参数无效则整批不发送。使用当前账户时可直接省略该字段。

| 价格关键字 | 含义 |
|---|---|
| mrxjg / mcxjg | 买限价 / 卖限价 |
| mrj1～mrj5 | 买一～买五 |
| mcj1～mcj5 | 卖一～卖五 |
| zxjg | 最新价 |
| ztjg / dtjg | 涨停价 / 跌停价 |
| "7.00" | 自定义每股价格 7 元 |

撤单不填写价格和数量：

```json
{"side":"cancel","code":"000009","notip":true}
```

全撤当前账户：

```json
{"side":"cancel","code":"all","notip":true}
```

全撤全部已登录账户：

```json
{"side":"cancel","code":"all","account":"all","notip":true}
```

`code=all` 是全撤委托；`account=all` 是全部已登录账户，二者作用不同。指定账号时将 ACCOUNT_ID 替换为实际账号。买入、卖出、撤单均可选择当前、指定或全部已登录账户。

### 按合同号撤单

按单个合同号撤单，仍发送到 `POST /order`：

```json
{"side":"cancel","contract":"00123456","account":"ACCOUNT_ID","notip":true}
```

信用账户按合同号撤单：

```json
{"side":"cancel","contract":"00123456","xytype":1,"module":"pyd","notip":true}
```

`contract` 只用于撤单，必须为字符串，不接受 JSON 数字、逗号列表或空白；和 `code`、原始 `h` 参数混用会在发送前报错。信用合同撤单使用 `xytype: 1` 选择信用账户上下文，目标直接由合同号决定，不填写 `credit: true`；`credit: true` 用于按股票或全部范围查询可撤清单。合同号撤单不需要预先获取可撤清单，也不依赖数据查询通道。

批量中每笔也可使用相同的 `contract` 字段。接口调试的交易方向可选择“按合同号撤单”，生成 JSON、Python 和 cURL；日常桌面交易按钮仍只提供全撤和撤当前票。Python 示例客户端提供 `cancel_contract("00123456", account="实际账号")`，信用账户再传 `xytype=1, module="pyd"`。

## 批量买入及其他批量操作

发送到 `POST /orders/batch`，将每笔单笔 JSON 放进 orders 数组：

```json
{
  "orders": [
    {"side":"buy","code":"000009","price":"mrxjg","amount":100,"notip":true},
    {"side":"buy","code":"600000","price":"mrxjg","cw":"1/10","notip":true}
  ]
}
```

每批 1～20 笔；每笔分别设置方向、股票、价格、数量和 account。省略账户时使用当前账户；指定账户要写在每笔中。批量提交不是原子事务：一笔失败不会撤回其他已提交的委托。各笔比例按交易端处理时的账户数据计算，不是固定同一资金快照。

返回 batch_id 和 orders，各笔 result 为提交结果。batch_id 现为不透明的 GUID 字符串，原样保存并用于 `GET /batches/批次编号`，不要转成整数或从本地序号推算；旧数字编号查询返回 404，不会命中新批次。每批生成独立编号，重启不再从 1 重新分配对外编号。批量合并回执按整批展示；不能仅凭返回数组顺序判断合同号属于哪笔订单。

提交和查询响应的 batch_size 是原批次笔数，complete 表示返回记录是否完整，不表示全部订单已完成。查询各条 batch_index 应覆盖 1～batch_size；记录不完整时不能宣称整批已结束。仍有待核对成员的批次会整体保留，包括其中已返回的成员；清空历史也遵守此规则。整批结束后，按最近完成时间作为一个整体参与历史清理。

```python
import atexit
import requests

# 程序启动时只创建一次；后续下单、查询和轮询共用这个 session。
# 不要放进每次调用的函数或循环里反复创建。
session = requests.Session()
atexit.register(session.close)  # 程序正常退出时关闭连接池

base = "http://127.0.0.1:8421"
headers = {"X-API-Key": "填入设置中的密码"}  # 仅手动关闭验证后可使用 {}
payload = {"orders": [
    {"side": "buy", "code": "000009", "price": "mrxjg", "amount": 100, "notip": True},
    {"side": "buy", "code": "600000", "price": "mrxjg", "cw": "1/10", "notip": True}
]}
response = session.post(base + "/orders/batch", json=payload, headers=headers, timeout=30)
response.raise_for_status()
result = response.json()
print(result)
batch_id = result.get("batch_id")
if batch_id is not None:
    print(session.get(base + f"/batches/{batch_id}", headers=headers, timeout=10).json())
# 等待中，继续查询原批次编号，不要重复提交整批。
```

软件“说明”的第二页“HTTP 请求生成/在线调试”支持单笔和批量：表单逐笔“加入批量”，或直接编辑 orders JSON，再复制 JSON / Python / cURL 代码。发送按钮会提交实际请求，下方自动查询回执。选择“数据查询”可填写参数或编辑自定义 JSON，生成持仓、当日委托、当日成交、资金的 JSON 请求体 / GET 地址 / Python / cURL，并在线发送只读查询，选择当前、指定或全部账户；支持 wait_ms，pending 时自动读取原 query_id 的结果。在线调试选择 JSON、Python 或 cURL 时发送 POST /query；选择 GET 地址时发送 GET 查询。标题和发送按钮会显示当前请求方式。查询结果显示完整原始 JSON，可选中或复制；查询不写入交易日志。

### 在线调试的 API 密钥

- **直接调试本机：** 默认选择“本机设置”，自动读取设置中已保存的密钥，发送请求及后续查询回执时都带上，无需重复填写。本机关闭验证后不带密钥；设置中更换并保存密码后，这里自动跟随。
- **查看与复制：** “显示密钥 / 隐藏密钥”切换明文显示，“复制密钥”复制实际密码。本机模式只读；修改、随机生成和保存服务端密码仍在设置页完成。
- **密钥不放进 JSON：** JSON 只放股票代码、数量、查询类型等业务参数。密码单独放在 HTTP 请求头 `X-API-Key`；POST 另外设置 `Content-Type: application/json`。生成器下方单独显示“请求头（不属于 JSON 参数）”，可显示或复制。**复制请求头会包含明文密钥。** GET 地址也不包含密码，不能仅凭粘贴网址完成有密码的调用。
- **复制代码自行运行：** Python / cURL 默认用 `API_KEY` 占位符，运行前替换为实际密码；勾选“代码带入密钥”后，预览及复制的代码直接包含当前明文密钥。此选项不影响在线发送，在线发送一直使用实际密钥。复制 JSON 或 GET 地址时仍须单独设置请求头。cURL 示例使用 Bash / Git Bash 的引号语法，Windows 也可直接使用 Python 示例。
- **调试其他服务：** 选择“手动填写”，填目标服务的密钥；修改服务地址会切换到手动模式，并清除自动带入的本机密钥，避免误带给其他服务。切回“本机设置”恢复本机地址和密钥。手动填写仅用于本页请求，不修改目标服务的密码。
- **返回 `401 Unauthorized`：** 目标服务开启了密码验证，但请求未带密钥或密钥不一致。先核对目标地址与该服务设置中的密码；仅目标服务关闭验证时才能留空。此错误发生在业务处理前，不是同花顺账户获取失败。

例如 Python 把两部分分开传入：`session.post(BASE + "/query", headers={"X-API-Key": "实际密码"}, json={"kind": "holdings", "mode": "ordinary"})`。开启验证时，查询、交易和读取回执都使用同样的请求头。

查询 JSON 请求体示例（可在“数据查询 → 自定义 JSON”中粘贴，也可由程序直接 POST 到 /query）：

```json
{
  "kind": "holdings",
  "account": "all",
  "wait_ms": 2000
}
```

`kind` 必填：`holdings` 持仓、`orders` 当日委托、`deals` 当日成交、`funds` 资金。`account` 选填，默认 `current`，也可填已登录账户号或 `all`；`wait_ms` 选填，默认 2000，范围 0～5000。以上 JSON 可直接提交到 `POST /query`，请求头为 `Content-Type: application/json`。也可选择等效的 `GET /query/holdings?account=all&mode=ordinary&wait_ms=2000`，两种方式不需要同时调用。

## 结果与日志

单笔返回 request_id、accepted、confirmed、status，以及 receipt 或 error。用 `GET /orders/原 request_id` 获取交易结果，不要拿 `/last` 代替。没有拿到 request_id 的不确定结果，需要核对当日委托，不能盲目重发。

| 字段或状态 | 含义 |
|---|---|
| accepted | 已取得交易端请求编号；不表示成交 |
| confirmed / success | 已获得可以确认提交结果的成功返回；不表示成交 |
| status=confirmed | 已确认委托提交结果，包括聚合撤单成功笔数或无可撤委托 |
| status=accepted | 已取得内部返回，但内容尚不足以确认成功 |
| status=uncertain | 结果不确定，按原编号继续核对，不自动重发 |
| status=rejected | 明确拒绝或失败，原因见 error |
| receipt | 完整返回文字；合同号和撤单成功笔数以这里实际返回为准 |

`GET /orders/:id` 的查询错误与原订单结果分开：记录缺失或过期返回 HTTP 404、`query_status=not_found`；暂时不可查返回 HTTP 503、`query_status=unavailable`；返回编号不匹配或格式无效返回 HTTP 502、`query_status=invalid_response`。这些响应均保留原 `request_id`、`status=uncertain`、`confirmed=false`，省略无法据此确定的 `accepted`，不会把原流水改为 Failed。404/503/502 都不能作为重新发单的依据；临时错误可按原编号稍后重查。

聚合撤单可能只有“成功笔数：3”，没有逐笔合同号；不会凭空生成合同号。`request_id`、`batch_id`、`query_id` 是三种不同编号，不可互换。HTTP 200/202 也不等于成交，须读取 JSON 内的状态。

v3 接受回执中边界完整的 1–32 位数字合同号，包括 `11` 等短合同号。“买入已提交”只表示提交结果，成交以券商记录为准。旧版本误判为“不确定”的已提交买入，不要因此重复发送；本次修复不会自动确认或重发旧记录。

当前版本的 `receipt` 可能附带下列诊断字段；HTTP 仍使用原来的 `request_id` 查询，不用内部编号代替：

| 字段 | 含义 |
|---|---|
| `native_task_id` | 同花顺内部任务流水号，仅在本交易进程内关联任务；不是券商合同号 |
| `native_task_pending=1` | 已绑定的原生任务仍待结果；即使 `execution_done=1`，仍按原请求编号继续查询 |
| `native_task_result=1` | 已在原生完成分支保存结果；是否提交成功仍以业务文字和 `confirmed` 为准 |
| `execution_done` | 原生执行函数是否已返回，与业务回执是否已保存分别记录 |

回执可以出现 `ACK` 与 `execution_done=0`：结果已保存，但函数还在收尾。后台会继续刷新执行状态和耗时，不覆盖已确认的结果。内部任务已析构且没有可确认结果时仍标为不确定。没有业务合同号的成功文字不会用内部任务号补成合同号。

异步提交通常先出现 `WAIT`、`execution_done=1`、`native_task_pending=1`：提交函数已返回，任务仍在处理，后续请求可以提交。此时函数的空返回或单个账户的部分结果不作为整笔最终结果；完整回执稍后更新原请求。提交前立即拒绝的明确原因仍会解析。未能绑定任务且返回也无法确认时保留不确定状态，并停止该批次剩余命令；不自动补发。

批量查询各笔 stage：Posted 等待回执，Submitted 已确认提交结果，Failed 明确失败，Timeout 等待超时（仍可查询迟到回执），Uncertain 结果无法明确确认，需核对原请求及券商记录。HTTP 请求失败或等待超时，不代表同花顺一定没有收到，请先查原编号再决定下一步。

回执在后台处理。界面已结束历史最多显示最近完成的 200 条，清理时不拆分批次；活动未完成请求单独保留（最多 2000 条），其批次中已完成的成员也一起保留。已脱离旧 DLL 实例的归档不占活动容量，仍须核对。清空界面历史不会清掉仍需处理的整批记录，也不会删除恢复证据。请求与回执证据持久保存到 `%LOCALAPPDATA%/ThsLink/request-history.jsonl`，重启后恢复待核对记录；文件包含交易命令、账户选择参数及回执，请按交易记录保管。调用程序仍应保存完整业务日志、请求参数、返回编号和查询结果。复制生成代码本身不发单。

## CLI 命令

```text
thslink.exe send buy 000009 mrxjg -cw 1/10 -notip
thslink.exe send sell 000009 mcxjg -cw 1/2 -account ACCOUNT_ID -notip
thslink.exe send cancel all -notip
thslink.exe send cancel all -account all -notip
thslink.exe result 请求编号
thslink.exe who
thslink.exe query holdings current
thslink.exe query orders all
thslink.exe query deals ACCOUNT_ID
thslink.exe query funds current
thslink.exe query-result 查询编号
```

CLI 与 HTTP 使用同一 DLL 通道；HTTP 字段 account、cw 等对应命令的 -account、-cw 等。长连接由当前驻留 ThsLink 进程持有；已运行桌面版或 HTTP 服务时，其他程序应通过 HTTP 调用，不要再同时启动另一个 ThsLink CLI 进程争用管道。

撤指定合同的命令示例：`thslink.exe send cancel -h ORDER_ID -notip`，把 ORDER_ID 换成实际委托合同号。

## 重连与更新

桌面版和纯接口版共用自动恢复流程。桌面版空闲时约每 3 秒尝试连接，纯接口版开启 `connect_bridge` 后每 5 秒触发一次；单次任务未结束时不启动重复恢复。连接失败累计 3 次后尝试现有 DLL 安全停止、卸载、重新加载、验证流程，完整重载至少间隔 30 秒，没有重试次数上限。恢复不退出或重启同花顺，也不重发旧交易。

仅“交易结果尚未确认”不再阻止重新连接或安全重载。重载前将原请求、已有编号、回执与 DLL 实例标识同步写入 `%LOCALAPPDATA%/ThsLink/request-history.jsonl`；写入失败则本轮不卸载。新交易也先保存发送记录，再写入管道。重载后旧结果仍为未知，不能视为失败或成功；旧 DLL 请求编号不再向新实例轮询。同花顺重启后仅在原进程已退出、路径一致时自动重新绑定。内部执行、原生任务、查询或回调未结束仍会阻止卸载；DLL 完全无响应时会记录失败并持续重试，不强制卸载。

在线更新只在用户手动点击检查时执行，不会启动或定时自动检查。新安装默认不内置更新地址；如需使用软件内更新，在设置中的 HTTP 接口区域填写可信的 HTTPS 发布信息地址。该地址须返回包含版本、发布说明和完整 ZIP 下载信息的 JSON。更新使用完整便携包，同时替换主程序、DLL 和加载器；安装前退出同花顺，个人配置保留。未配置地址或检查失败时，请手动替换完整程序包。


## 长期运行与技术诊断

DLL 请求结果记录最多 2000 笔；容量不足时只回收已确认或人工核实的记录，批量记录整体回收。未知结果不会因超过 5 分钟就被清除或自动解除保护。主程序已结束历史与未完成请求的容量规则见上文。等待中的请求继续按原编号查询；函数已返回且任务没有待完成结果、结果仍不可确认时停止自动查询，仍需核对券商记录，不自动重发。

技术文件日志默认关闭。如需排查问题，可在程序旁创建 `diagnostics/enabled` 空文件，日志写到该目录。默认忽略其他版本遗留的全局诊断标记；如确需使用 `%LOCALAPPDATA%\ThsLink\diagnostics/enabled`，还须在当前程序目录创建 `diagnostics.use-global` 空文件。便携目录标记优先。删除当前启用标记约 5 秒内生效；使用全局方式时也可删除 `diagnostics.use-global` 停用。DLL 使用自身所在目录，不是同花顺 EXE 的目录。关闭诊断仍保留正常缓存读取、账户校验与超时处理；额外追踪、分页诊断、诊断文本构造和阶段计时跳过。

`startup.log` 记录主程序入口、首次连接和界面更新，`loader.log` 记录 DLL 探测、加载和握手，`bridge.log` 记录 DLL 工作线程与管道，`timing.log` 在交易发生时记录交易计时，不交易时可能没有该文件。每条记录含时间戳、进程号和相对该组件首次记录的毫秒数；各文件最多 1 MB，各保留 3 份轮换备份。这些是技术诊断文件，不是持久交易日志。


## 请求容量与超时

- HTTP 同时允许最多 64 个待处理或执行中的调用（单笔、批量和查询共用容量）。满额立即拒绝；被拒请求不会延后自动发送。
- HTTP 请求等待发送的有效期为 5 秒。在取得发送锁后、实际写入交易命令前再次检查；过期或 HTTP 服务已经停止时返回“本次未发送”。服务重启后，上一轮尚未发送的请求也不会继续发送。
- 已经写入交易命令后，通信超时仅表示结果未知，禁止自动重发。调用方应核对回执或委托状态。
- 客户端每次管道通信有 10 秒期限。DLL 长连接正常空闲时持续等待；收到消息后的分段读取有 5 秒期限，响应写入与等待客户端确认共享 5 秒期限。客户端分段读取完整响应，超过 64 MB 明确报错，不伪装为空回执。
- 未知结果不会因等待时间到期变成成功或失败；同实例可继续查询，安全重载前先归档，不再仅因业务结果未知阻止恢复。正常退出仍保留人工核对保护。原生执行、任务、查询或回调未结束时不能卸载 DLL。旧单不自动重发；实例已变化时停止查询旧编号，按本地流水及券商委托/成交核对。

标题栏“置顶”和浅色 / 暗黑主题会保存。点“−”最小化到任务栏；点“X”隐藏到系统托盘。单击托盘图标恢复，右键“退出应用”结束程序。后台继续处理 HTTP 请求和回执；关闭“手动交易”才会暂停自动读票和交易热键。股票区域可切换手动输入和恢复跟随，手动模式不会被自动读票覆盖，重开需重新输入代码。

## 兼容窗口与查询诊断

普通双击 `thslink.exe` 使用无边框窗口。虚拟机或远程桌面出现黑屏时，先退出 ThsLink，再双击同目录 `兼容运行.bat`；也可执行 `thslink.exe --compat-window`，使用系统标题栏窗口。

主动查询应同时检查 `status`、`complete` 和各账户的 `error`。`status=unchanged` 表示同花顺这次没有提供新的结果，不等于没有委托。只有本次响应明确附带 `cached=true` 的表才作为缓存展示，最新性和完整性按对应标记判断；不要自行把上一次结果当成本次新结果。可重新发起查询。HTTP 502 仍表示真正的查询失败。

需要排查时，在程序与 DLL 所在目录创建 `diagnostics/enabled` 空文件，重试查询后查看 `diagnostics/query.log`。结束诊断后删除 `enabled` 即可关闭记录。诊断目录和日志不随正式包分发。


## 连接身份与安全退出

连接检查区分交易端未启动、多个目标、旧/不同构建 DLL、管道无响应，以及当前 xiadan.exe 内部结构不兼容。DLL 身份包含版本、构建、路径与宿主 PID/路径；交易发送前再次核对身份，交易端改变时拒绝发送。退出上次程序不等于 DLL 已卸载；同构建 DLL 可复用，不同构建不能盲目替换。

GUI 关闭到托盘保持运行；从托盘选择退出才执行安全检查。CLI 使用菜单 0/q 或 Ctrl+C。未完成委托、仍在处理的查询、账户操作、连接任务或未知交易结果会拦住退出，提示原因；只读查询超时结束后允许再次检查，卸载仍须关闭并等待观察回调退出。空闲后停止新任务，安全卸载 DLL，确认模块消失再退出。保留 xiadan.exe，不撤单、不重发。交易超时不会仅因过了五分钟就变成“已确认”。

人工核对不确定结果只能在券商记录核实后执行：GUI 退出提示窗口直接列出记录并提供核对按钮，CLI 菜单 5 选择列表序号并用 y 确认。它保留原回执和不确定状态，只记录人工核实，绝不把未知委托伪造成成功。原生调用、关联任务或查询仍在运行时继续保护退出；提交函数已返回不代表任务已完成，不能用人工核对解除仍在处理的任务保护。

HTTP `/health` 继续返回 status 和 bridge_pid，并增加 state、message、bridge：区分 ready、busy、different_build、legacy_bridge、terminal_incompatible、unresponsive、not_connected 和 exiting。身份路径供受配置密钥保护的接口诊断使用，不包含密钥或账户号。


### 交易端版本显示与退出操作

设置→同花顺连接显示 xiadan.exe 文件版本、PID、路径、构建标记和映像大小，并提供“刷新版本”。显示不依赖 DLL 注入：旧版、其他构建或未适配版本仍可读取文件版本。手动路径模式也可在文件未运行时检查版本；没有版本资源或没有权限时明确显示读取失败原因。

版本信息读取与兼容判定分别进行。固定构建和 2026.10.20.0 的支持范围见本文开头；未知构建仍须严格验证。信用账户读取和四类查询已接入；当前现场核对不代表其他查询和交易功能全部验收。HTTP /health 增加 terminals 与 terminal_scan_error；已有 status/state/message/bridge_pid 字段保留。

程序对已知和未知构建执行完整自动发现与严格验证。检查出现歧义或关键接口关系无法确认时拒绝连接。对已审阅范围内的地址和部分结构变化可自动适配；接口逻辑或布局发生未建模变化时仍须人工更新，不能仅凭版本更新幅度推定兼容。

首次只读扫描的成功与失败均缓存到 DLL 生命周期结束，操作前继续复核实际代码和观察入口。连接摘要、INFO 和 HTTP `/health` 的 `bridge.automatic_adaptation` 显示 `family`、`mode`、`adjusted_roles`、`connection_frame`、`scan_ms`。首次 INFO/READY 最多等待 60 秒，其余交易期限和短探测不变，不会为适配自动重发请求。适配器只读本地映像，不联网、不下载规则、不执行订单探测。文件版本可显示不等于兼容；实际逻辑、结构或未建模关系变化仍需分析。

安全退出窗口不要求填写编号或密码。只有不确定结果时才列出待核对记录，用户选择并勾选已在券商记录确认，再“确认核对”；核对不改变原始回执为成功。安全退出无法完成时提供“强制退出 ThsLink”“重新尝试安全退出”和“继续运行”。强制退出只结束 ThsLink，不关闭交易端或强制卸载 DLL。


权限不足时设置页显示“ThsLink普通权限 / 交易端管理员”及具体处理；连接在加载DLL前拒绝。HTTP /health 的 terminals包含 current_elevated、terminal_elevated、bridge_access_error；无法握手且权限检查未通过时state为permission_denied。权限未知不会猜测为管理员不匹配，而是明确访问被拒绝。程序不会自动提升权限或关闭交易端。


### 异常状态详情与退出选择

主窗口底部 DLL 未连接、HTTP 关闭/启动/异常状态显示红色问号，点击后打开原因详情，包括交易端文件版本、产品版本、PID、路径、构建和权限，以及实际连接/HTTP启动错误。正常DLL已连接、HTTP运行中显示绿色普通文字，不响应点击。关闭的HTTP开关仅说明服务未开启，不等于程序故障。

选择退出后先尝试安全退出。权限不足、任务忙或 DLL 无法确认时，提示具体原因，并提供“强制退出 ThsLink”“重新尝试安全退出”和“继续运行”。退出检查仍在等待时，也可直接点击“强制退出 ThsLink”，无需再确认或先完成核对。强制退出只关闭 ThsLink 及其 HTTP 服务，不关闭交易端，不强制卸载 DLL；未确认退出记录保留，下次启动重新检查连接。

正常安全退出和强制退出都保留交易端。“与交易端一起退出”选项已移除。强制退出后桥接 DLL 可能仍驻留在交易端，再次启动时按身份检查结果重连。退出不会撤销已提交委托，也不会把未知回执改为成功；调用方应保存原请求编号，并在券商委托/成交记录中核对，禁止自动重发。


### 已知回执边界

当前版本已移除由 `sync=1` 启用的原生事件等待循环，正常异步任务缺少即时回执不会阻挡后续提交。仍不能保证内部函数永不阻塞：提交前检查、行情读取、锁和分发调用仍可能不返回，此时仍保留共享执行器的串行保护。30 秒超时只改变本地显示，不取消委托、不停止跟踪迟到回执、不自动重发。未完成和不确定请求达到容量上限时会拒绝新请求，不能无限保留。在线调试遇到临时 GET 错误时可能停止自动跟踪，可手动刷新原请求；后台交易流水独立跟踪。

## 信用交易（v0.3.3）

使用信用交易时，请在同花顺中只登录一个账户，ThsLink 使用当前账户。HTTP 省略 `account`（或填写 `"current"`），原始命令省略 `-account`。信用买卖直接使用同花顺当前账户，不要求先获取信用账号，也不因账户类型未运行验证而拒绝发送；信用全撤需要读取账户身份并取得完整可撤清单，规则见下文。多账户信用路由尚未验证，程序不额外检测或拦截多账户登录。

| 业务 | 买卖方向 | xytype |
| --- | --- | --- |
| 担保品买入 | buy | 1 |
| 担保品卖出 | sell | 2 |
| 融资买入 | buy | 3 |
| 融券卖出 | sell | 4 |
| 买券还券 | buy | 5 |
| 卖券还款 | sell | 6 |

快捷按钮编辑、批量编辑和 HTTP 请求生成器均可选择业务。撤单命令可携带对应 `xytype`；普通撤单省略 `xytype` 和 `credit`，直接走原生入口。信用撤单全部业务需明确选择 `credit`，不会自动识别切换。参数必须是表中的编号，买卖方向须与业务一致；错误参数会在发送前拒绝，避免意外按普通交易执行。

**撤单方式：** “全撤”和“撤当前票”都可编辑，默认“普通撤单”。普通模式直接走原来的同花顺入口，不读取账户列表，不自动判断或切换信用模式。已有设置缺少新选项时仍按普通模式处理。

信用用户在按钮编辑或“说明 → HTTP 请求生成/在线调试”中，选择撤单方向后，将交易业务设为“信用撤单（全部业务）”。生成器会在 JSON、Python 和 cURL 中带上 `credit: true`；所有信用请求同时带上 `module: "pyd"`，加入批量时保留完整参数。HTTP 明确添加 `"credit":true`；原始命令及 `thslink.exe send` 添加 `-credit`。这些是 ThsLink 撤单选项，不用于买卖，用户请求中不能与 `xytype` 混用。单独使用 `xytype` 走原生撤单路径，不等同于信用全业务清单方式。

以下完整信用请求适用于四个已适配版本，以及通过原生接口兼容检查的新构建。生成参数不要求先连接，实际发送仍需连接并通过原有校验。

```json
{"side":"cancel","code":"all","credit":true,"module":"pyd","notip":true}
```

撤单统一使用 `POST /order`，必须填写 `"side":"cancel"`。信用撤当前票将 `code` 换成实际六位股票代码；程序只撤这只股票。命令行分别为：

```powershell
thslink.exe send cancel all -credit -notip -module pyd
thslink.exe send cancel 600000 -credit -notip -module pyd
```

信用方式仍核对目标账户及新可撤清单。省略账户即当前账户；指定账号或 `account=all` 时明确绑定对应账户，所选目标必须都是信用账户，不将普通账户混入信用计划。初次核对请只登录一个信用账户，多账户信用路由尚未运行验证。

只有完整的新清单才能进入撤单：查询失败、超时、无更新、分页未完成、合同号缺失或账户变化，返回明确的“本次未撤单”。信用撤单在串行提交线程中先准备清单、再提交各段；同一批后续命令不能抢先，准备失败或内部调用结果不确定时停止该批后续发送。不等待券商最终回执。此查询仍占用既有查询通道，准备期间其他提交可能按原有忙碌规则被拒绝并提示本次未发送。普通撤单没有这一步。数量较多时自动分段，每段绑定独立原生任务并汇总；部分成功、失败或不确定不会报成全部成功，不确定不自动重发。全撤只覆盖这次清单，不包含之后新发出的委托；成功笔数表示撤单委托提交笔数，最终状态以券商记录为准。

普通账户全撤沿用原路径。v3 的信用清单子命令使用 `cancel -h 合同号列表 -account 账号 -xytype 1`，避免同一个账号误匹配普通账户。这是内部可撤清单分段提交；对外单笔 `-h` 和 HTTP `contract` 仅接受单个合同号。此处 `-xytype 1` 选择信用账户上下文，不把合同清单筛成担保品买入；用户用 `credit: true` 或 `-credit` 选择撤单范围，无需填写内部合同清单或子命令的 `xytype 1`；信用命令统一携带 `-module pyd`。直接按合同号使用 `-h ... -xytype ...` 时，目标由合同号决定，不能把编号当成该合同的额外业务筛选。用户已反馈 v3 信用撤单在当前环境通过验收；其他券商及版本仍需分别核对。

**完整信用命令（v7）：** 选择信用买卖或信用撤单即生成带 `-module pyd` 的完整命令，例如 `cancel all -credit -notip -module pyd`。四个已适配版本（远航 2026.05.06.0、普通版 2026.07.02.0 / 2026.09.15.0 / 2026.10.20.0）和通过完整兼容检查的新构建，使用同一信用参数规则；不再要求匹配 10.20 指纹。预览、复制、发送和请求日志使用同一条完整命令，DLL 校验后不重复添加。普通交易不添加 module。

本机和远程请求生成器均在信用 JSON 中写入 `"module":"pyd"`，Python、cURL 和批量请求使用同一份参数。HTTP 服务在命令生成、流水登记前应用同一规则；旧手写请求省略模块仍兼容。显式 module 只允许信用请求中的字符串 pyd；重复命令参数、其他模块值、普通请求带模块会被拒绝。批量命令导入支持完整参数。此规则不免除交易端原生接口、账户和数据完整性校验，也不保证所有未来版本或券商都已实测通过。

**在线调试核对（v7）：** 选择信用业务时显示 module:pyd，不以连接状态或本机/远程地址改变信用参数。JSON、Python、cURL 与待发送确认使用同一份请求；单笔和批量均保留完整字段，混合批量的普通请求不会被加上 module。手写 JSON 不被静默改写；非法 credit 类型、credit/xytype 混用、业务方向错误、普通请求带 module 或非字符串 pyd 会在确认前提示。生成、复制及打开确认本身不发送请求，点“确认实际发送”才调用服务。查询无需上述交易参数。

信用全业务撤单仍是撤单计划：执行时读取实际可撤清单并按账户、合同号生成子命令。预览不会提前查询或交易，也不是执行成功凭据。

完整融资买入 HTTP 请求示例：

```json
{"side":"buy","code":"000001","price":"zxjg","amount":100,"xytype":3,"module":"pyd","notip":true}
```

完整原始命令示例（`send` 使用原有发送/回执链路）：

```text
thslink.exe send "buy 000001 zxjg 100 -xytype 3 -notip -module pyd"
thslink.exe send "cancel -h 123456 -xytype 1 -notip -module pyd"
```

便捷命令的预览支持 `--xytype 3`，例如 `thslink.exe buy 000001 10.00 100 --xytype 3`；只有显式加 `--send` 才发送。批量 HTTP 请求中每笔分别填写 `xytype`。普通交易无需添加该字段，旧设置保持原行为。

信用交易仍使用原有内部执行器和异步任务回执，不新增同步等待，也不自动重发不确定订单。现场已观察到用户提交的信用买入成功回执；用户已反馈 v3 信用撤单验收通过，六类业务、账号切换及多账户信用交易仍未全面验收。信用账户读取和四类查询已接入，用法见下文。


## 信用账户查询

桌面在 **编辑 → 查询** 手动选择“普通查询”或“信用查询”，保存后持仓、当日委托、当日成交和资金均按所选模式执行。程序不按账户类型自动选择，也不在失败后换另一种模式重试。

HTTP 沿用上述四类接口，显式传 `"mode":"credit"` 进行信用查询，`"mode":"ordinary"` 进行普通查询；省略 mode 固定为普通查询（包括旧客户端），不再自动识别。GET 使用 `&mode=credit`；CLI 示例：`thslink.exe query holdings current credit`。查询不加 `xytype`、`credit`、`module` 或 `notip`。`account=all` 对所有目标使用同一个所选模式，请勿依赖逐账户自动切换。

返回顶层 `mode` 表示实际选择的查询模式；`accounts[].account_type` 仍是读取到的账户类型，仅作元数据，不控制查询入口。`/who` 读取账户信息，不受查询模式影响。普通和信用查询均须使用与 EXE 匹配、支持 query-mode-v1 的新 DLL。

信用持仓示例：`{"kind":"holdings","account":"current","mode":"credit","wait_ms":2000}`。

初次验证请只登录一个信用账户，使用 `account=current`，依次查询持仓、当日委托、当日成交和资金，并与同花顺当前账户显示核对。信用结果保留原始列名，不套用普通资金字段规则。查询失败时不会自动改用普通账户查询，不使用旧表填补结果。`pending` 时继续读取同一 `query_id`，不要重复提交。

旧构建和 10.20 契约族均保留信用查询工厂与账户字段校验。现场读取信用账户及当日委托的结果不代表所有查询和券商兼容均已完成。请整体使用同一构建的程序包，不混用旧 DLL。
